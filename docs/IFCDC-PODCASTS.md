# IFCDC Podcasts

Public entry: `/podcasts`, linked from the website and listener navigation. Uses existing radio listener sign-in and creator display name; no HQ role is granted. A creator may create up to ten series and 500 episodes per series. Published listings are public; drafts appear only in the authenticated owner's studio. Episodes can be unpublished or deleted; series deletion removes its episode listings without deleting external source files. Account deletion requires deleting owned podcast series first.

Supported in this release: HTTPS links to creator-hosted audio, video, or downloadable content. Browser-supported direct audio/video media plays on the episode page, with an external source link for other formats or playback errors. External sites may block embedding or require their own accounts. Files are not fetched by the IFCDC server. Only the creator display name is public, not email or listener favorites. Mutations require the existing listener session and approved website origin/header; all mutations check series ownership.

Not delivered: direct podcast file uploads, conversion of arbitrary formats, RSS distribution/import, subscriptions, payouts, moderation queue, or podcast insertion into live radio. Never describe this release as accepting every possible upload format. Creators must confirm publication rights. External media requests disclose a visitor's IP to that host; playback uses preload none and no-referrer, with no autoplay. Metadata is stored in the existing IFCDC database; its deployment persistence and backups remain prerequisites for production reliability.

Apply after the programming/import diagnostics update. Run `node --import tsx --test script/podcasts.test.ts`, `npm run check`, and `node --import tsx script/build.ts`. API integration test covers draft privacy, ownership isolation, origin checking, invalid links, publishing, account deletion protection, and series cleanup. Browser visual QA has not been performed in this environment.
